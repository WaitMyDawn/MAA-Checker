MAA-Checker —— Minecraft 整合包可行性检验器（v0.1）
=====================================================

它是干什么的
------------
直接检验你【已经装好】的整合包实例：自动启动游戏、盯日志判断能不能进主菜单、
读懂崩溃原因，然后按最小改动把包修到能启动，全程留台账、可一键还原。

四种动作（都遵循"先补装、补不到才摘除"）：
  A 升级加载器：就地升级 NeoForge 到满足要求的最新版本（改实例版本 JSON，有备份）
  B 补装前置  ：从 Modrinth 下载缺失的必需前置（记录项目/版本/哈希）
  C 摘除模组  ：把导致崩溃的模组移到 bin\ 目录（不是删除），可还原
  D 不做取舍  ：只按"能不能跑起来"办，不判断哪个模组"核心"

怎么用
------
1. 双击 launch.bat（lite 版）或 MAA-Checker.exe（exe 版）
   两者都需要 Java 21+：launch.bat 会自动找（HMCL 自带的运行时也算），
   exe 版也自带查找逻辑，找不到会弹带 Java 下载指引的提示
2. 界面里选一个实例 → 点【开始检验】（只看看能不能跑）
   或点【自动修复】（按 A/B/C 自动修到能启动）
3. 改动都能在界面的"台账"区看到，点【还原到检验前】即可全部回滚

目录说明
--------
  logs\<实例>\<时间>\   每一轮的完整日志、启动命令、报告（report.txt / report.json）
  state\<实例>\         改动台账（<会话>-round-N.json/.md）、墓碑、下载缓存
  bin\<实例>\round-N\   被摘除的模组文件（还原就是从这里移回去）
  config.properties     记住了游戏目录与代理设置

关于网络（重要）
----------------
Modrinth 的下载地址（cdn.modrinth.com）在国内直连基本不可用（实测 4 次里 3 次连不上，
通了也只有几 KB/s）。镜像站 mcimirror 只加速"查信息"（快 10 倍），不承运文件。

本工具的策略：
  - 有可用代理 -> 下载走官方本站（经代理）；查信息仍优先镜像加速
  - 没有代理   -> 查信息走镜像；下载先试镜像入口（0.1 秒判死）再试直连，
                  两者都失败就弹窗，让你选：
                    已开好代理继续 / 本次只做摘除（不补装）/ 停止检验并还原
  - 单文件判据：连接 8 秒；连上后【5 秒内平均 < 13KB/s 就判"不稳定"并立刻放弃】
                （不是"5 秒必须下完"——大文件证明速度起来后会一路下完）

代理怎么开：
  - Clash / V2Ray 打开【系统代理】即可，本工具会自动探测，并做端到端探活
    （端口在听 -> 隧道能建 -> 真能访问 Modrinth，三层都过才算可用）
  - 也可以点界面上的【设置代理…】手填，例如 http://127.0.0.1:7890
  - 「端口开着但系统代理关着」也能被扫到（会扫 7890/7891/7897/10809/10808/2080/1080/8080）
  - 拿不准就点【检测网络】：10 秒左右告诉你镜像/代理/真下载分别通不通

命令行等价用法（排查用）
--------------------------
  java -jar maa-checker.jar --list                列出识别到的实例
  java -jar maa-checker.jar --check "实例名"       跑一轮检验
  java -jar maa-checker.jar --fix   "实例名"       自动修复
  java -jar maa-checker.jar --restore "实例名"     还原到检验前
  java -jar maa-checker.jar --repair-libraries "实例名"   补齐缺失的库（游戏报"找不到主类"时用）
  java -jar maa-checker.jar --test-proxy          实测网络能不能下模组
  java -jar maa-checker.jar --diagnose <日志文件>  离线分析已有的崩溃报告
  java -jar maa-checker.jar --help                全部参数

关于 libraries（共享地基，别乱删）
----------------------------------
<游戏目录>\libraries 是所有实例共用的库目录；被误删会让所有实例都起不来
（报错常是"找不到主类 cpw.mods.bootstraplauncher.BootstrapLauncher"）。
本工具升级加载器时会往这里写库（运行时必需品，不删）；万一被删，用
    java -jar maa-checker.jar --repair-libraries "实例名"
按版本 JSON 的 url + sha1 补齐即可，不需要重装游戏。

关于 HMCL 整合包（重要）
--------------------------
如果这个包是用 HMCL 导入的（实例目录里有 modpack.cfg），那么 HMCL 每次【启动】
都会先按包内清单检查一遍文件，缺失的自动下载回来 —— 也就是会把本工具摘掉的模组
原样补回来（等于白修）。

本工具在一次真的改动了文件的修复之后，会把标记文件改名来阻止这件事：
    modpack.cfg  ->  modpack.cfg.maa-checker-bak   （内容一字未改）
报告（fix-summary.md）与界面弹窗里都会写明原因；代价是 HMCL 里【更新整合包】的
入口会消失。想恢复：点【还原到检验前】会自动改回，或手动把文件名改回来。

注意
----
- 检验会【真的启动游戏】：每轮 40~90 秒，进主菜单后再观察 10 秒确认不会刚进去就崩
- 检验前请关闭该实例已经在运行的游戏（工具也会拦一次）
- 所有改动都在实例目录里就地做，但都有台账与备份；不放心可以先备份整个实例目录
